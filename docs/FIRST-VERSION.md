# 智能罗盘：立方日程区域与路径导航

版本 1.3.3（2026-10-06），Minecraft 1.21.1 / NeoForge 21.1.219 / TLM 1.5.3。TLM 及匹配源码来自 Modrinth Maven，无需 Create。客户端和服务端应使用相同附属版本。

## 六个工具

主手持 **Kappa's Smart Compass（河童的智能罗盘）**，按住工具菜单键（默认左 Alt）、滚轮选择、松开确认。菜单不暂停游戏，保留已有抬升动效和 12×12 GUI 像素图标。“应用到女仆”位于最后，已有罗盘的工具编号保持兼容。

下面的“使用”“攻击”“潜行”均指游戏内动作，默认分别为右键、左键、Shift；交换鼠标按键或改绑键盘后，操作随设置变化。HUD、物品提示和服务端操作消息显示玩家当前的真实按键。

| 工具 | 操作 |
| --- | --- |
| 立方框选 | 使用两个对角方块添加长方体，含两端，默认为工作区；攻击框删除该区和关联边；潜行＋使用取消未完成角点 |
| 路径节点规划 | 使用已有区域或路径点选起点；使用其他位置在玩家脚部所在格添加节点并连接；使用另一节点连接；攻击路径点删除，攻击区域断开其边 |
| 标记选区 | 使用已有立方框，循环工作区→休息区→睡觉区→工作区；保留节点编号、坐标和所有连接 |
| 重命名区域 | 使用立方框打开名称编辑，最多 64 个字符；留空恢复“区域 N”编号；回车或保存确认，Esc 取消 |
| 调度选项 | 使用打开工作区时刻表；编辑目的地卡片和延迟条件；主界面确认后保存草稿 |
| 应用到女仆 | 使用自己的女仆应用全部区域和图；潜行＋使用女仆清除她的自定义配置，恢复原日程区域 |

编辑工具点击女仆不会应用草稿，也不会误触坐下。需要修改已应用的配置时，先编辑草稿，再选择应用工具重新应用。重命名和调度编辑均只修改罗盘草稿；保存时若罗盘槽位、工具或草稿已变化，则拒绝过期编辑，不覆盖新数据。

**潜行＋清除节点键**（默认 Shift+V）在立方框选工具中清除所有三种类型的立方选区，保留中间路径点及它们之间的边；在路径工具中清除中间路径点，保留所有立方选区及区域之间的直接边。仅移除被删除节点关联的边。其他工具中该键不清除内容。两项按键均跟随游戏设置。

路径编辑没有“结束”操作，每次创建、连接和删除均立即保存。路径模式下潜行＋使用与普通使用相同。清除立方选区后，剩余路径点仍可编辑，新添加的区域不会覆盖它们。

智能罗盘在 TLM 创造模式物品栏，也可用原河童罗盘、红石粉、铜锭各一个无序合成。当前复用原罗盘外观，以独立名称和黄色物品名称区分。命令：`/give @s touhou_little_maid_custom_workspace:kappa_smart_compass`。

## 日程与目的地

开启女仆的 Home 模式后，根据 TLM 当前日程使用对应的自定义区域：WORK 对应工作区，IDLE 对应休息区，REST 对应睡觉区。

- 未自定义调度时，工作区按添加顺序循环，只计算被标记为工作区的区域。默认每区 2400 个工作游戏刻。
- 进入休息或睡觉日程时，对该类型每个候选区域规划路线，优先选择有图路线且总路程最短的区域。如果所有候选都没有图路线，则选择直接距离最近的区域，直接导航。
- 当前休息或睡觉目的地在转场期间保持稳定。日程改变时重新选择，防止移动途中每刻来回改目标。
- 每种日程独立判定：存在该类型立方区时优先使用附属区域和图；没有时完整使用 TLM 原罗盘坐标、范围、搜索和行为。可以只配置任意一种或两种区域，两种罗盘的应用先后顺序不影响优先级。
- 工作游标和工作额度独立保存，休息和睡觉不会消耗或重置它们；返回工作时导航至原来的工作区后继续累计。

所有三种自定义日程转场都优先使用路径图。区域也是图节点；女仆在已知节点内时，从当前位置所在节点规划至目标。女仆在所有节点之外时，取得目标所在的**整个连通分量**，先导航至其中离她最近的中间路径点，再沿图到达目标。不会把另一个连通分量中的近点作为入口。目标分量没有中间路径点，或当前所在节点与目标不连通时，回退到直接导航。

路程是女仆当前位置至首个目标节点，以及后续各节点中心之间的三维游戏坐标距离之和。它不预计算 A* 的实际绕障长度。到达中间区域只推进路线，不开始该区域的工作、娱乐或睡觉；完成全部必经节点且进入最终区域后才交回原任务逻辑。详见 [路径图说明](ROUTE-GRAPH.md)。

## 工作区调度编辑

按机械动力列车时刻表的“目的地＋离开条件”结构组织。每张卡片代表一个停靠工作区，卡片上行点击打开目的地编辑器，只列出工作区，可以按名称搜索；下方条件条点击打开条件编辑器。当前仅有“延迟”条件，填写 0～1728000 游戏刻，滚轮或加减按钮调整，Shift 每步 15 刻。条件确认返回主表，不立即写入罗盘；主表右下角确认才保存，取消或 Esc 丢弃本次界面改动。

卡片可以删除、复制、上移和下移，最多 128 条。允许同一个区域出现在多个条目中，每个条目拥有独立延迟。循环开启时最后一条回到第一条；关闭时完成最后一条后留在最后工作区，继续原任务，但不再次轮换。单条循环表留在同一区。延迟为 0 时到达后的首个允许工作 tick 进入下一条，不跳过入区检查。

时刻表先到第一条目的地；到达并进入工作阶段后开始累计该条条件。满足后导航至下一条目的地，仍优先使用路径图。休息、睡觉、转场和不能工作的状态暂停条件进度。工作游标、条件进度与完成状态存入女仆，回来继续原条目。

首次打开未自定义的调度会显示默认轮换作为编辑起点，未编辑直接确认仍保持默认配置；“恢复默认”撤销自定义表，重新按添加顺序和 workTicksPerArea 运行。自定义表保存的是每条明确的游戏刻数，之后调整全局默认额度不会更改它。

删除区域会删除指向它的条目并更新其余引用；将工作区改标为休息或睡觉区，会移除该区的调度条目。名称变化不改变图连接或调度目标。清除路径点保留调度，清除全部立方区域同时清除对应调度。编辑后需重新应用到女仆。

参考：[Create ScheduleScreen](https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/trains/schedule/ScheduleScreen.java)、[TimedWaitCondition](https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/trains/schedule/condition/TimedWaitCondition.java)。附属独立绘制纸面、卡片和控件，不引入 Create 的类、资源或依赖。单位固定为游戏刻，不增加秒或分钟切换。

## 边界、任务与显示

入区严格使用女仆脚部所在方块的 XYZ 坐标与框选边界比较，不向上扩展一格，不把“接近中心”或“寻路结束”当作入区。框选必须包含实际可站立的坐标；只选实心地板不算到达。每段导航朝当前节点的中心寻路，但实际进入框即可推进。

区内候选目标搜索、实体脚部坐标及区内导航节点使用当前立方体边界。床、娱乐设施和家庭用餐垫先过滤当前区域，再按 TLM 原条件挑选目标，避免区外较近设施遮蔽区内有效设施。床头的方块坐标也应包含在睡觉区内。

任务拿到候选目标后的执行方式仍由 TLM 决定。例如任务操作相邻方块、产生范围效果等，不由附属统一限制最终影响范围。这延续此前约定：附属改变选区和目标搜索，不改写各具体任务的作业语义。

工作区红色、休息区绿色、睡觉区蓝色，与 TLM 原版河童罗盘一致；瞄准框附加黄色外框，女仆当前目的区域附加白色外框，保留原类型颜色；中间路径点和边青蓝色，未完成框选预览蓝色。每个立方区域框上方都有朝向摄像机的两行标签，显示名称或默认编号，以及区域类型。1.3.1 修正文字横轴翻转引起的背面剔除，并将两行标签整体放在顶面上方。过长名称仅在世界标签中截短，完整名称仍保存并用于界面搜索。持智能罗盘瞄准女仆可查看她自己的配置和当前导航节点。

## 计时和超时

工作额度只按服务端女仆 tick 累计，不使用现实时间，也不将 /time set 的时间跳变算入额度。进入工作区、Brain 为 WORK、允许移动时每 tick 加 1。前往区域、休息、睡觉、坐下、乘坐、拴住、打开女仆界面、惊慌、禁用 AI、关闭 Home 或实体不 tick 时不累计。

默认轮换的单工作区不会反复触发转场。自定义表依次执行条目，不取并集，不同时搜索其他区域。前往区域超时默认 0，关闭超时跳过。配置大于 0 时按每个导航段允许移动的游戏刻计时，到达一个节点后重新计时；超时后工作日程跳至下一个条目或默认工作区，休息或睡觉日程尝试另一个候选区。没有后续目的地时继续尝试当前区。

图路线尚未完成时，不执行 TLM 的日程返回传送兜底，避免跳过必经点。直接导航保留原兜底。寻路仍复用 TLM 的原实现，不增加自动扩大 A* 搜索范围或节点预算的机制，见 [NAVIGATION-RECOVERY.md](NAVIGATION-RECOVERY.md)。

## 保存、兼容和配置

罗盘草稿与女仆数据各自保存完整不可变快照。应用后改写、清空、删除或销毁罗盘不会影响女仆。各女仆的区域、名称、路径图、调度表、目的地、剩余路线、工作及调度游标、额度与完成状态独立保存。完整图和当前工具存档；未完成的角点、临时连接起点不存档，工具切换或切出主手时取消。

罗盘计划与女仆状态各自保存 `data_version: 1`；女仆内嵌计划也拥有自己的版本字段。无版本数据按旧版 0 加载并在重新保存时升级，数据版本独立于 mod 发布版本。专门的迁移入口在解析当前结构之前执行，详见 [数据版本与迁移](DATA-VERSIONS.md)。

旧版本的所有区域自动视为工作区，原工作游标、额度和图继续保留。应用或清除自定义区域不会改写 TLM 原工作、休息和睡觉坐标。原河童罗盘保持 TLM 的全部交互；其旧附属草稿组件不生效，也不会自动迁移到新物品。

重新应用草稿并移除当前类型的立方区时，会立即恢复其原版区域，停止旧的自定义导航。原版罗盘仍可更新自己的三种坐标；已有自定义类型继续优先，未自定义类型立即采用新坐标。进入原版休息或睡觉期间保存工作游标和额度；回到自定义日程时，从当前实际位置重新选择图路线。名称、图和两种罗盘的数据均可共同保存到女仆存档。

计划绑定一个维度；跨维度编辑前先清除立方区域与路径点。只允许女仆主人应用和清除。范围扫描不主动加载或生成区块，节点之间应有可通行的路线。

配置文件：游戏目录 config/touhou_little_maid_custom_workspace-common.toml。服务端配置决定运行行为。

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| workTicksPerArea | 2400 | 默认轮换额度和新调度条目的初始延迟；自定义表保留每条明确的刻数 |
| travelTimeoutTicks | 0 | 每个导航段的超时刻数，0 关闭跳过 |
| maxAreasPerMaid | 16 | 工作、休息、睡觉三种立方选区合计上限 |
| maxAreaEdge | 64 | 每个区域单轴最大格数 |
| maxAreaVolume | 131072 | 每个区域最大体积 |
| candidateBudget | 2048 | 每次任务搜索最多检查的候选方块数，下一次继续扫描 |

每图最多 256 个中间路径点、2048 条无向边。

六项配置均由运行逻辑或编辑验证使用，没有无效项。升级不会覆盖已有配置文件；若旧文件仍设置 `travelTimeoutTicks = 1200`，需要手动改为 0 才会关闭超时跳过。

## 构建与验证

使用 Java 21，运行 .\gradlew.bat build 和 .\gradlew.bat runGameTestServer。发布包为 build/libs/touhou_little_maid_custom_workspace-1.3.3.jar，测试代码和结构不进入发布包。

1.3.0 通过 41 项 JUnit 和 25 项 NeoForge GameTest，包含此前区域和路径全部回归，以及名称清理与保存、指定工作区、逐条延迟、重复目的地、循环与一次执行、零延迟、删除后的引用更新、过期编辑保护、实际逐节点转场和重复条目、完成后留在最后工作区、女仆与罗盘独立存档、跨休息与睡觉保存自定义条件进度。1.3.1 仅调整区域渲染，构建和 41 项 JUnit 通过，并完成实际世界渲染验证。

1.3.2 构建、41 项 JUnit、27 项 GameTest 通过，新增三种区域所有七个非空组合与原版罗盘共同应用、覆盖、清除、存档，以及仅自定义工作区时实际使用原版睡觉区的验证。可选 .\gradlew.bat runClient -PcompassControlsTest 在独立开发存档交换攻击／使用鼠标键，改绑菜单／潜行／清除键，经真实客户端按键和服务器交互验证六种工具的使用和攻击行为、服务端动态按键提示，并生成 build/compass-controls/swapped-keys.png。测试结束恢复开发客户端原按键。

1.3.3 构建、49 项 JUnit、28 项 GameTest 通过，新增无版本及显式旧版本的 JSON/NBT 迁移、双层版本写入、名称/图/调度与进度保留、未来和异常版本拒绝，以及真实罗盘组件和女仆存档升级验证。真实客户端确认独立五帧贴图加载正确，六种工具的交互和版本化数据同步均通过。
