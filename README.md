# 女仆自定义工作区 · Touhou Little Maid Custom Workspace

![智能罗盘的立方区域、区域标签与路径图演示](exp.png)

[English](README_en.md)

为 **Touhou Little Maid（车万女仆）** 添加河童的智能罗盘，让每只女仆拥有独立的立方工作区、休息区和睡觉区。你可以用路径节点引导她绕过障碍，也可以用调度表安排她依次前往不同工作区，按游戏刻工作后再轮换。

## 开发阶段说明

这是本项目的首个公开版本，当前版本 **1.3.3**。已完成构建、49 项单元测试、28 项游戏集成测试，以及客户端按键、界面和贴图验证。复杂地形及第三方任务仍欢迎实测反馈。

如果遇到女仆卡住、区域切换异常或界面问题，请在 [Issues](https://github.com/hyt2002/Touhou_Little_Maid_Custom_Workspace/issues) 提供模组版本、触发步骤、区域与路径节点截图，以及相关日志。尤其请说明女仆是否已进入区域、是否开启 Home，以及节点之间是否实际可通行。

## 用法

### 河童的智能罗盘

**Kappa's Smart Compass（河童的智能罗盘）** 可以在 TLM 创造模式物品栏找到，也可以用 **河童的罗盘、红石粉、铜锭各一个** 无序合成。

主手持有智能罗盘，按住工具菜单键（默认 **左 Alt**），滚动鼠标滚轮选择工具，松开确认：

| 工具 | 操作 |
| --- | --- |
| 立方框选 | 使用两个方块角点添加立方区域；默认标记为工作区 |
| 路径节点规划 | 选择起点，创建或连接必经路径点 |
| 标记选区 | 使用已有立方框，在工作区 → 休息区 → 睡觉区之间轮换 |
| 重命名区域 | 使用立方框打开命名界面，名称与类型显示在框上方 |
| 调度选项 | 使用打开工作区调度表，编辑目的地及延迟条件 |
| 应用到女仆 | 使用自己的女仆，复制整份配置；女仆开启 **Home** 后生效 |

本文中的“使用”“攻击”“潜行”是游戏动作，默认分别为右键、左键和 Shift。左右键互换或重新绑定按键后，操作与游戏内帮助会跟随实际设置。菜单键和清除键也可在按键设置中修改。

### 立方区域

1. 选择“立方框选”，使用两个角点添加一个区域；可以连续添加多个区域。
2. 选择“标记选区”，使用对应的框，设置工作、休息或睡觉类型。
3. 可用“重命名区域”添加名字，方便辨认和在调度界面选择。
4. 最后用“应用到女仆”工具使用自己的女仆，并开启 Home。

工作区为 **红色**，休息区为 **绿色**，睡觉区为 **蓝色**，与原版河童罗盘一致。区域边界包含两端的方块坐标，必须包含女仆实际能站立的脚部坐标；只框选实心地板不会视为到达。睡觉区也应包含床头坐标。

### 路径节点规划

路径点可以帮助女仆绕过长墙、门口或其他需要分段前往的地形。

1. 选择“路径节点规划”，使用一个已有区域或路径点，设为起点。
2. 走到你希望女仆经过的位置。使用非已有节点的位置，可以点击方块或空气；罗盘记录的是 **玩家此刻的脚部方块坐标**，生成单格节点并连接起点。
3. 新节点会成为下一次连接的起点。继续添加节点，或使用另一个已有节点，将两者连接。
4. 把路径连接到目标区域，再应用到女仆。

路径边可以双向通行，不需要“结束编辑”。攻击中间路径点会删除该点及关联边；在路径工具中攻击区域只删除它的连接，保留区域本身。

女仆优先沿图上的最短路线逐节点导航，实际进入节点框才推进。没有合法图路线时，直接前往目标区域。女仆不在任何节点内时，会先进入目标连通分量中离她最近的中间路径点。多个休息区或睡觉区会按图上总距离选择目的地。

这里的最短距离按游戏坐标计算，不会预先模拟真实绕障路程。节点应放在可站立的位置，相邻节点之间需要可通行。详细规则见 [路径图说明](docs/ROUTE-GRAPH.md)。

### 工作区调度

“调度选项”采用目的地卡片和独立条件编辑器，交互参考机械动力的列车时刻表。目前只支持 **延迟 x 游戏刻**：女仆到达指定工作区后开始工作计时，满足条件后前往下一条目的地。

可以选择工作区、调整延迟、重排、复制或删除条目，并选择循环执行或执行一次。关闭循环后，女仆完成最后一条会留在最后工作区继续原任务。未自定义调度时，按区域添加顺序，每区默认工作 **2400 游戏刻**。

计时使用游戏刻，前往区域、休息、睡觉或不能工作时暂停；不使用现实时间。界面确认保存到罗盘后，需要重新应用到女仆。

### 删除与清除

- 立方框选工具中，攻击已有立方框可删除该区域及相关引用；潜行＋使用取消未完成的框选。
- 潜行＋清除键（默认 **Shift+V**）：立方框选工具清除全部工作、休息和睡觉立方区域，保留中间路径点；路径工具只清除中间点，保留区域。被删除节点的关联边同时移除。
- 应用工具中，潜行＋使用自己的女仆，清除她身上的自定义区域和路径设置，恢复原版区域逻辑。

## 兼容性说明

- **普通罗盘和智能罗盘可以共存。** 每种日程区域有立方区时优先使用本附属设置，没有时使用 TLM 原版罗盘的坐标和行为。普通罗盘继续保留原有功能。
- **配置写在女仆身上。** 应用后修改、清空或销毁罗盘都不会影响她；重新应用才会覆盖她的自定义配置。不同女仆的数据相互独立。
- 女仆仍使用 TLM 的原有寻路。复杂绕障可以通过必经节点引导；入区严格按框选坐标判断。
- 本附属改变区域和候选目标搜索，具体任务对目标的操作及范围效果仍由 TLM 或对应任务模组决定。
- 区域计划绑定一个维度，范围搜索不会主动加载或生成区块。
- 罗盘计划和女仆状态保存独立的数据版本号，无版本旧数据会自动兼容并在重新保存时升级，见 [数据版本与迁移](docs/DATA-VERSIONS.md)。

## 配置

配置文件为 `config/touhou_little_maid_custom_workspace-common.toml`，服务端配置决定运行行为。

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `workTicksPerArea` | 2400 | 默认轮换额度及新调度条目的初始延迟 |
| `travelTimeoutTicks` | 0 | 前往区域超时游戏刻数；0 关闭超时跳过 |
| `maxAreasPerMaid` | 16 | 工作、休息、睡觉立方区域合计上限 |
| `maxAreaEdge` | 64 | 单个区域每条轴的最大格数 |
| `maxAreaVolume` | 131072 | 单个区域最大体积 |
| `candidateBudget` | 2048 | 每次任务搜索的候选方块预算，下次继续扫描 |

自定义调度保留每条明确的刻数，不受之后修改默认额度影响。升级不会覆盖已有配置文件中的超时数值。

## 开发与文档

使用 **Java 21**。Gradle Wrapper 会通过 Modrinth Maven 获取 TLM 和对应源码，不需要复制游戏目录中的 TLM JAR。

```shell
./gradlew build
./gradlew runGameTestServer
```

Windows 下使用 `gradlew.bat`。发布文件位于 `build/libs/`，开发测试代码及测试结构不进入发布包。GitHub Actions 会执行构建与游戏集成测试。
